# 상태 계약

업무 종류별 정의의 정본은 [status-contract.json](../status-contract.json)이다. 코드·표시 이름·색상 토큰·상태 정렬·필터 분류·허용 동작을 이 파일에서 정하고 서버와 브라우저 정의를 생성한다. 현재 운영 판정은 [openrig_bridge/status_policy.py](../openrig_bridge/status_policy.py)가 맡는다. Windows C# 전환의 생성물·판정 대조와 적용 범위는 [Windows 실행 구조](windows-runtime.md)에 있다.

## 적용 원칙

- 저장 상태와 표시 상태를 별도 필드로 유지한다. 화면은 서버 판정을 다시 추측하지 않는다.
- 사유 코드는 제어에, 문장은 설명에 쓴다. 수동 재시도와 자동 재시도·해제 조건을 구분한다.
- 일감·워커·프로그램 승인·서버 상태·작업 결과는 각각 정의한다. 실행 종료로 QA·배포 성공을 추정하지 않는다.
- 미정의 값은 상태 미확인으로 표시한다. 정의 밖 값과 호환되지 않는 판정에는 변경 동작을 제공하지 않는다.
- 자료의 조회 시각과 정의 버전·지문을 전달한다. 읽기에 실패하면 이전 상태임을 표시하고 지난 응답이 새 화면을 덮지 않게 한다.
- 화면에 필요한 정의는 프로그램에 포함한다. 다른 프로그램의 실행 여부가 기본 표시를 좌우하지 않는다.
- 상태 변경의 원본과 사유·처리 시각을 보존한다. 민감한 실행 데이터는 시험 근거에 넣지 않는다.

## 생성과 검사

정의를 바꾼 뒤 python tools/state-contract.py 로 생성한다. python tools/state-contract.py --check 는 생성물 불일치를, node tools/check-state-contract.cjs 는 공용 정의 밖의 중복 상태표·문장 기반 제어·전역 일감 문맥의 재도입을 검사한다. 알려진 값 전체, 별칭, 미정의·누락·특수 키, 응답 순서와 버전 불일치를 함께 시험한다.

일반 시험 관문에도 생성물·정책 검사를 넣는다. 변경 전후 수용 기준과 실행 근거는 [검증 결과](verification/state-contract/acceptance.json)에 둔다. 사용자 확인과 독립 QA는 자체 시험과 구분한다.

화면 전용 적용은 tests/ui_checks.py, 전체 적용은 tests/selftest.py에서 같은 화면·상태 계약 관문을 실행한다. 상태별 집계와 일일 점검 필터는 정의에 등록된 상태 전체에서 생성한다.
