# MooKKo 담당 공통 규칙

## 일하는 방식
- 일감 하나가 한 턴입니다. 받은 일감을 끝까지 처리하고 보고서(JSON)로 끝냅니다. 다음 일감은 프로그램이 보냅니다.
- 보낼 수 있는 담당(canSend)에게만 보냅니다. 범위 밖 일이 필요하면 그 담당이나 PM에게 요청합니다. 요청은 편집 허가가 아닙니다.
- 사용자 결정이 필요한 일(범위, 우선순위, 비용, 보안 예외, 언어·런타임, 돈 정책)은 임의로 정하지 않고 `blockedOn: external:user-<영문식별자>`로 올립니다.
- 사용자에게 승인·확인을 묻지 않습니다. 스스로 판단할 수 있는 일은 근거를 남기고 진행합니다.

## 기준
- 기준은 "가장 높은 수준"입니다(사용자 2026-10-20: 알리페이·알리바바급 속도·보안·안전, 99.99%). 낮은 목표를 임의로 두지 않습니다.
- 개인 운영이라 운영비가 낮아야 합니다. 메모리·프로세스 수·외부 서비스 비용을 늘리는 설계는 근거를 적습니다.

## 코드 (정본: MooKKo `AGENTS.md`, 관문: `docs/policy/gates.md`)
- 서버 실행 코드는 Rust만 씁니다. 모든 crate 루트에 `#![forbid(unsafe_code)]`. Python·PowerShell은 CI·시험·개발 도구에만.
- 커밋 전에 Linux(WSL `MooKKo-Linux`)에서 `scripts/ci/check-all.sh`를 실제로 돌리고 명령·종료 코드·결과를 보고합니다(fmt·clippy -D warnings·test·deny·audit + forbid-unsafe·경계·주소 하드코딩·스택 검사). Windows에서 돌린 결과는 통과로 세지 않습니다. 하네스가 후보 커밋에서 같은 검사를 다시 돌리고 그 결과만 믿습니다.

## 정해진 방식 (사용자 결정, 어기면 하네스가 반영하지 않음)
- 모든 앱은 공용 서버 엔진 하나를 씁니다. 서비스 crate는 엔진 포트만 쓰고, HTTP 서버·HTTP 클라이언트·DB 드라이버·gRPC·캐시 클라이언트 crate를 직접 쓰지 않습니다. 엔진에 없는 기능은 바탕(foundation) 담당에게 요청합니다.
- 전부 모듈화: 바깥 시스템은 엔진 포트 + 어댑터 crate + 적합성 시험으로만 붙입니다.
- 포트·주소(IP·호스트·URL·host:port)는 코드·상수에 두지 않고 JSON 설정에서만 읽습니다. 시험도 fixtures JSON에서 읽습니다.
- 웹 화면은 `web/`(pnpm)에서 React + TypeScript + Tailwind CSS만 씁니다. 내부 화면은 Vite SPA(엔진이 정적 파일 서빙), Next.js는 공개 SEO 화면 앱에서만. API 클라이언트는 `.proto`에서 생성한 것만 씁니다.
- 이름에 Rust를 붙이지 않습니다(MooKKo, `mookko-*`).
- 자기 담당 경로(owns)만 고칩니다. 커밋 전에 `git diff --cached --name-only`로 확인합니다.
- 지금 C# 판(MooKKo)은 읽기만 합니다. 읽기 전용 사본 위치는 `.runtime/context/reference.md`에 있습니다. C# 판을 고치거나 실행 데이터를 만들지 않습니다.

## git
- 커밋 첫 줄 `[영역] 한 일`, 본문에 무엇을 왜 했고 어떻게 확인했는지. 본문 끝에 `작업자: <엔진>`(예: `작업자: Claude Code`, `작업자: Codex`). 작성자 신원은 프로그램이 넣으니 따로 설정하지 않습니다.
- push·reset·rebase·태그·브랜치 이동을 하지 않습니다. main 반영은 다른 엔진의 독립 QA 영수증을 확인한 프로그램만 합니다.
- 다른 담당에게 파일을 넘길 때는 자기 owns 경로에 커밋하고 커밋 SHA와 저장소 안 경로를 적습니다.

## 보고
- 한 일, 바꾼 파일, 실행한 검증(명령과 결과), 남은 일을 적습니다.
- 실행하지 않은 검증을 통과로 쓰지 않습니다. 문서 작성, 담당 등록, 시험 개수만으로 기능 완료를 주장하지 않습니다.
- 개발이 끝난 커밋은 자기 QA 담당에게 `commit:<40자 SHA>` 태그가 붙도록 보고서 messages로 검사를 요청합니다(QA는 다른 엔진이 맡습니다).
